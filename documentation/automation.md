# Automation and Agent Boundaries

## Codex 任务

- 触发：用户在网页发送消息，或确认一个允许的自动动作。
- 所有者：用户账户；实际执行者是该账户绑定的 Gateway。
- 输入：用户消息、指定工作区、明确上传的附件、允许的任务配置。
- 工具：由本机 Codex app-server 根据 Gateway 策略提供；CodeHarbor 不额外授予任意 shell。
- 输出：结构化状态事件、工具摘要、最终 Agent 消息和错误状态。
- 硬约束：工作区白名单、设备授权、任务并发锁、超时、大小限制、撤销和 kill switch。

## 子代理

目标是将 Codex 暴露的子代理事件关联为父任务/子任务树。是否可见、粒度和可中断性必须先做协议探针；在验证前，UI 只承诺显示已确认的工具/事件，不承诺完整子代理拓扑。

## 模型与配置

网页只提交结构化、白名单化的模型和策略值。Gateway 负责检查本机可用性；不允许网页直接传递任意 CLI 参数或覆盖完整配置文件。模型切换按“新任务优先、下一 turn 视协议支持、全局默认最后”的顺序实现。

## 控制措施

- 每个命令带幂等键、设备 ID、任务 ID 和过期时间。
- 云端记录动作审计，但默认不记录完整源码和密钥。
- 连接断开时停止接收新命令；已运行任务的行为由用户选择的本地策略决定，并在网页显示。
- 服务端和桌面端都提供设备撤销/kill switch。
